Features

Everything Flighty knows, one command away.

Reads, never writes, your data

Flights, friends, stats and connections come from the app's local SQLite database, opened read-only. No sync server, no scraping.

Times that make sense

Every time is shown in the airport's own zone. JSON carries utc, local and tz, so nothing is ambiguous.

Search the way you type

Accent-insensitive matching on airports, cities and airlines: con dao finds Côn Đảo, zurich finds Zürich.

Built for scripts and agents

-o json on every command and stable exit codes, so a shell script or an AI agent can branch on the result instead of parsing prose.

Add and follow flights

flighty add QR111 2031-03-14 adds a flight you're on; follow tracks someone else's. They show up on your phone like any other.

Stats, delays, connections

Distance and time in the air, delay history for a route, layover lengths between your flights, and what your Flighty Friends are flying.

An MCP server included

flighty mcp exposes the same functions as tools to Claude and other MCP clients. Same code path as the CLI, same safety rules.

One static binary

Written in Rust. No Node, no Python, no runtime to install. Your auth token is read per call, never logged, and wiped from memory after use.

Install

Ready before boarding.

Needs macOS, the Flighty Mac app installed and signed in, and a Rust toolchain.

  1. 1

    Install the binary

    cargo install --git https://github.com/theanhgen/flightydeck
  2. 2

    Check it can see Flighty

    flighty about
  3. 3

    List what's coming up

    flighty list --upcoming

MCP

Give your agent a window seat.

Safety

Cleared for reads. Writes need clearance.

Every command belongs to one safety class. The policy lives in the shared library, so the CLI and the MCP server enforce exactly the same rules.

Read

Always on

list, get, search, current, status, delay, friends, stats, connections, airports, airlines, about.

Write

On unless read-only

add, follow. Checks the flight isn't already tracked, and spaces out calls to the API.

FLIGHTY_READ_ONLY=1 turns off every write, and overrides everything else.

Destructive · experimental

Off by default

remove. Needs FLIGHTY_ALLOW_REMOVE=1 and --yes. The sync semantics it relies on aren't fully verified yet.

  • Talks only to https://api.flightyapp.com, with redirects disabled.
  • The auth token is read from the local database per call, never logged or printed, and zeroized after use.
  • Bad input is rejected before any network call.

Exit codes

CodeMeaning
0OK
1Error (including "Flighty is syncing, retry")
2Bad input, caught before any network call
3Not ready: Flighty not installed or signed in, token expired, schema changed, owner unresolved
4Flighty API error
5Refused by policy (read-only, remove not enabled)
6Not found

FAQ

Before you fly.

Is this made by Flighty?

No. flightydeck is an independent, unofficial project. It isn't made by, endorsed by, or affiliated with Flighty.

Do I need a Flighty subscription?

You need the Flighty Mac app installed and signed in. flightydeck can only see and do what your account in the app can.

Does it work on Linux, Windows or iPhone?

No. It reads the Mac app's local database, so it runs on macOS only.

Can it break my Flighty data?

Reads open the database read-only. Adding and following go through the same API the app uses. Removing flights is off unless you explicitly enable it, and FLIGHTY_READ_ONLY=1 turns off all writes.

What happens when Flighty updates?

The app's database and API are private and can change without notice. flightydeck checks the schema before each query and exits with code 3, naming the missing column, rather than returning wrong data.

Where does my token go?

Only to api.flightyapp.com, in the request header, the same way the app sends it. It's never written to logs, error messages or JSON output.
